# V2.3 Delta — Public Wallet Mint Counters

The latest reviewed GameEngine makes both per-wallet mint mappings public:

```solidity
mapping(address user => mapping(address collection => uint256 amount))
    public s_amountMintPerCollection;

mapping(address minter => uint256 mintedAmount)
    public s_normalMintAmount;
```

This frontend now consumes those autogenerated Solidity getters directly.

## Public Mint
Read:

```solidity
s_normalMintAmount(address wallet) -> uint256
```

The Public Mint console now shows:
- `YOUR PUBLIC MINTS X / 4`
- remaining public mints for the connected wallet;
- a progress bar;
- a quantity selector capped at `4 - s_normalMintAmount(wallet)`;
- `PUBLIC MINT LIMIT USED` when the wallet has exhausted its public allowance.

The frontend never assumes that Community Pre-Mints consumed this counter. The GameEngine keeps the two counters separate.

## Community Pre-Mint
Read for each invited collection:

```solidity
s_amountMintPerCollection(address wallet, address collection) -> uint256
```

The Community Pre-Mint console and directory now show:
- exact Gluttons already pre-minted by the connected wallet for that collection;
- exact remaining wallet allowance (`maxPerWallet - used`);
- community allocation remaining;
- holder eligibility;
- quantity capped by the minimum of wallet allowance, community supply remaining and global supply remaining.

A holder whose wallet allowance is exhausted sees `COMMUNITY MINT LIMIT USED` before signing instead of discovering it through a revert.

## Authority
These counters improve UX but do not replace contract enforcement. `mint()` and `preMint()` remain the final authority for limits and eligibility.
